- **Plus de push direct sur `main`** : le ruleset `protection-main` de `kraken-bootstrap` oblige à passer par une pull request, donc aucun commit n'arrive sur `main` sans que la CI ait tourné dessus (même moi, je me fais refuser le push).
- **Deux checks obligatoires avant le merge** : `kraken / lint-test` (ruff + pytest) doit être vert, et `kraken / build-push` aussi, qui construit l'image depuis le `Dockerfile` : un test cassé ou un `Dockerfile` qui ne build plus bloquent le bouton Merge. Je l'ai vérifié avec la PR #1, où j'avais faussé une valeur attendue : `lint-test` est passé au rouge, `build-push` a été ignoré et GitHub a refusé la fusion jusqu'à ce que je corrige.
- **Une seule CI pour tous les jobs, et seule `main` publie** : ces checks viennent du workflow réutilisable `kraken.yml` (dépôt `kraken`), et l'image n'est poussée sur GHCR, taguée par SHA, qu'après le merge sur `main` ; sur une PR elle est seulement construite, donc rien de non validé ne peut finir dans le registre.
