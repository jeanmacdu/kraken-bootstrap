- **Ordre des instructions et cache** : je copie d'abord `requirements.txt` seul pour installer les dépendances, puis seulement le code. Résultat : quand je modifie `app/main.py`, Docker reprend le `pip install` depuis le cache (c'est la couche la plus lourde, 307 Mo) et ne refait que la copie du code. Avec ma première version (`COPY . .` en tête), pip se relançait à chaque build, même quand je n'avais rien touché.
- **Image `slim` et `.dockerignore`** : en passant de `python:3.12` à `python:3.12-slim`, l'image est passée de 2,4 Go à 599 Mo sur disque (de 579 Mo à 132 Mo en taille brute). Le `.dockerignore` m'évite d'embarquer `.git`, mon `.venv` (compilé pour macOS, donc inutile dans le conteneur), les sorties, les tests et les caches : le contexte est plus léger et le cache n'est plus invalidé pour rien.
- **Utilisateur non-root et variable d'environnement** : le job tourne avec un utilisateur `app` (uid 1000) et non en root, ce qui limite les dégâts si le conteneur était compromis ; je lui ai donné les droits sur le code et le dossier de sortie. Grâce à `OUTPUT_DIR`, je peux choisir où le fichier est écrit sans toucher au code, par exemple sur mon poste avec un volume (`-e OUTPUT_DIR=/out -v "$(pwd)/out:/out"`), et sans volume il écrit simplement dans `output`.
